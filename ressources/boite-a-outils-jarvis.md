## Automatismes

- Hook de fin de session : sauvegarde le workspace sur GitHub (`.claude/hooks/auto-commit.sh`)
- À chaque `/prime` : vérification des mises à jour des skills suivis, appliquées d'office
- Barre d'état : modèle et taille du contexte (vert < 100k, jaune < 150k, rouge au-delà), script `~/.claude/contexte.py`
- Hook à chaque message : prévient Claude à 120k et 180k de contexte (même script). Compactage automatique d'Opus à 200k en dernier recours
- Agent `mecanique` (Sonnet, `~/.claude/agents/`) : Claude lui confie les tâches mécaniques de plus de ~5 actions
- Agent `lecteur` (Haiku, `~/.claude/agents/`, lecture seule) : recherche dans les fichiers, extraction de faits, collecte web sans jugement (dont la collecte de `/morning`). Biais : rapporte sans trier, donc le tri reste à Claude
- Hook `outils.py rappel` (à chaque message, `.claude/hooks/outils.py`) : si le message contient un mot-clé d'une ligne « Pour plus tard », signale l'outil à Claude, une fois par discussion. Muet sinon, donc sans jetons
- Hook `outils.py journal` (après chaque skill, agent, MCP ou outil en ligne de commande) : une ligne par jour et par outil dans `usage-outils.csv`. Au bilan mensuel, ce qui n'a jamais servi est retiré
- Hook `outils.py filet` (avant chaque commande, modification de fichier ou appel Supabase, depuis le 9/11) et partie skills de `outils.py rappel` : signale un skill installé mais pas chargé quand l'action ou le message le concerne, une fois par discussion. Écriture Supabase, migration, montage Remotion, commit ou déploiement de code : action retenue une fois, le temps de charger le skill. Rien pour `/taste`, `/grill-me`, `/nightwork`, ni pour `tdd` (indétectable). Tableaux `SKILLS_MESSAGE` et `skills_de_l_action` à compléter quand un skill manque son moment
- Hook `boite-vers-agence.sh` (fin de session, `.claude/hooks/`, depuis le 11/11) : envoie une copie de ce fichier dans `agence/ressources/boite-a-outils-jarvis.md` dès qu'il change, pour le seul Chercheur d'outils de la machine à contenu. Résultat dans `auto-commit.log`
- Hook `titre.py` (global, `~/.claude/titre.py`, depuis le 4/11) : nomme chaque discussion d'après le premier message qui n'est pas une commande (donc pas `/prime`), par un appel à Haiku (~1 000 jetons, ~8 s une fois par discussion, rien dans la discussion elle-même). Ne remplace jamais un titre posé, `/rename` reste possible
